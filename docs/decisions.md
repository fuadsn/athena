# Shared implementation contracts

Gate 0, 17 October 2026. The coordinator owns `packages/contracts`, root dependencies and runtime integration. Propose contract changes before editing shared files.

- The PRD is the scope authority. All business values are confirmed graph data. Source JSON contains historical facts only; `evals` never enters runtime ingestion or prompts.
- Root TypeScript aliases resolve packages from source. Node services run with `tsx`; Next.js runs at port 3100, runtime at 4100, Lab at 4200, FalkorDB at 16379.
- `GraphStore` in contracts is the graph/learning/runtime seam. The graph implementation must create real labeled relationships and implement the five mandatory relationship queries. JSON properties may preserve full records, but procedure and authority decisions must traverse graph edges. No in-memory authoritative fallback.
- Graph revision starts at zero. Publishing and authority assignment increment it; ordinary work writes do not. Published sources/procedures are immutable. Draft edits precede publication. Plan hashes bind request revision, procedure, knowledge revision, resolved parameters, steps, role and assignment.
- One runtime MutationBroker serializes all writes, knowledge updates, approvals and guarded Lab operations. Before every mutating Lab call it checks current graph state inside this lane. No model-generated graph writes.
- Lab API schemas and `LabClient` are in contracts. Write token stays server-side. The Lab computes `operationHash(tool, resourceId, body)` itself and requires a matching submitted hash. Operation key is `requestId/stepId`. A duplicate key with changed semantic input conflicts. Resource mutation and operation receipt are one atomic file commit. Lookup returns the original operation; identical retries can return an `ALREADY_APPLIED` receipt. No company policy belongs in the Lab.
- Binding grammar: request keys are `id`, `customerId`, `customerName`, `ownerEmail`, `requestedDays`; rule keys reference scalar Rule keys; output keys are `id` or `createdAt` and identify a prerequisite step; derived key `expiryFromCreatedAt` uses the referenced create step's persisted timestamp plus the plan's approved duration. The engine validates bindings and dependency edges before any mutation.
- Learning uses `ModelAdapter.turn` with strict Responses function tools and a fresh input list per episode. Live adapters never silently fake output. Test adapters are constructed only under tests. Model steps are bounded by shared episode limits. Structured candidate output remains proposed until owner review.
- `Review` explicitly confirms normal/extended durations, member access, approval role and inactive configuration/activation dependencies. Runtime compiles these human-confirmed edits into the small rule grammar and validates evidence. Candidate steps and observations remain inspectable.
- Web proxy issues signed local demo actor sessions using `DEMO_SESSION_SECRET`. All runtime routes except health require the signed cookie or token; arbitrary body actor IDs are rejected. Local persona controls are labeled and unavailable outside demo mode. Root runtime implements public API endpoints from the PRD plus `/session` and `/health`.
- Next.js browser code imports contracts as types only: runtime hash helpers import Node crypto. Initial UI can use typed placeholder state but the final demo must use real API results. No generated success timeline.
- Lanes: A owns graph, learner and their tests; C owns Workspace Lab, HTTP client and Lab integration tests; D owns web and browser tests. Coordinator owns runtime, executor, root scripts and cross-layer integration. Keep reports factual.

Foundation contracts are an implementation baseline. Any necessary change is recorded here and communicated to all affected lanes.
